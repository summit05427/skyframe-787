# Skyframe 787 · 适配设备

> 用途：参赛表「08_适配设备」填写、评审现场设备选择、录屏与展厅部署。
> 结论：**以 PC 桌面端为主，平板/手机可完整浏览但性能有限；必须支持 WebGL2 并开启硬件加速。**

---

## 1. 一句话结论

| 项 | 结论 |
|---|---|
| 适配类型 | **PC（桌面端）** 主推；平板 / 手机为补充支持 |
| 最低分辨率 | 建议窗口宽 ≥ 360px；完整体验建议 ≥ 1280×720 |
| 最佳分辨率 | **1920×1080**（三栏完整、无需滚动） |
| 浏览器 | Chrome / Edge 110+；Firefox 110+；Safari 16.4+ |
| 图形能力 | **WebGL2 + 硬件加速**，缺一不可 |
| 网络 | **不需要**；单文件内联，支持 `file://` |
| 输入 | 键鼠；触摸屏支持单指旋转、双指缩放/平移 |
| 不支持 | VR / AR 头显、手柄、摄像头、麦克风、指针锁定 |

## 2. 桌面端

### 2.1 推荐配置

| 档位 | 配置 | 预期体验 |
|---|---|---|
| 推荐 | Windows 10/11 或 macOS 12+；独立显卡（GTX 1050 / M1 及以上）；Chrome / Edge 最新版；系统缩放 100% | 预计 45–60 FPS（未实测，按核显数据推算） |
| 可用 | Intel Iris Xe / UHD 核显；Chrome 158；1080p；DPR 1 | 1080p 26–33 FPS（本次实测） |
| 最低 | 4 核 CPU、8GB 内存、支持 WebGL2 的集显 | 720p 可操作，复杂模式可能掉到 20 FPS |

### 2.2 本次实测环境与数据

- 环境：Windows 11、Chrome 158.0.8127.89（Headless new）、Intel UHD Graphics（ANGLE D3D11）、DPR 1、本地服务器。
- 首屏：1920×1080 约 **3.5 s** 完成启动（应用就绪约 3.0 s）；1600×900 约 **3.55 s**；`file://` 1600×900 约 **3.32 s**。
- 帧率：

| 模式 | 1600×900 | 1920×1080 |
|---|---|---|
| 外观 | 41.1 FPS | 31.0 FPS |
| 透视 | 36.6 FPS | 28.4 FPS |
| 剖视 | 33.4 FPS | **26.0 FPS** |
| 分解 | 42.8 FPS | 33.5 FPS |
| 材料 | 40.2 FPS | 32.8 FPS |

> 以上为核显数据。独立显卡通常可到 50–60 FPS；低端设备 1080p 可能低于 25 FPS。

## 3. 平板与手机

### 3.1 布局变化

| 宽度 | 布局 |
|---|---|
| > 1180px | 桌面三栏：左部件树 + 中 3D + 右信息卡 + 底部控制台 |
| 900–1180px | 顶栏流式；左栏改抽屉（左上角列表按钮）；控件网格 2 列 |
| 820–900px | 压缩模式胶囊 |
| ≤ 820px | 主题切换隐藏；信息卡改为底部浮层（仅选中时出现）；底部控制台默认收起；控件网格 1 列 |

### 3.2 触摸操作

- 单指拖动：旋转；
- 双指捏合：缩放；
- 双指拖动：平移；
- 点击热点或部件：选中；
- 无长按、无双击手势；无手势冲突处理（例如页面滚动），因为页面本身不滚动。

### 3.3 移动端注意事项

- 首屏在手机上可能 5–8 s，取决于 GPU 与内存。
- 默认收起控制台；需要先点底部抓手展开。
- 128GB 存储、4GB 内存级旧机型可能因显存不足掉帧或崩溃。
- iOS Safari 需 16.4+；低电量模式可能限制 WebGL 性能。
- 横屏体验优于竖屏；竖屏时信息卡会占 44vh。

## 5. 图形能力要求

- **必须 WebGL2**：three.js 0.187 的渲染路径依赖 WebGL2。
- **必须开启硬件加速**：Chrome「设置 → 系统 → 使用图形加速功能」。
- 渲染器参数固定：像素比上限 2、4096² 阴影、PCF 阴影、ACES 色调映射、4× MSAA 后期目标。
- **没有画质档位**：项目未实现「高/低画质」切换，低端设备只能通过降低窗口分辨率或系统缩放缓解。
- **没有 WebGL2 降级页**：创建渲染器失败时页面会停在启动遮罩，不会给出友好提示。现场演示前必须先在目标机器上打开一次。

## 6. 权限与隐私

| API | 是否使用 | 说明 |
|---|---|---|
| 摄像头 `getUserMedia` | 否 | 不请求 |
| 麦克风 | 否 | 不请求 |
| 指针锁定 `requestPointerLock` | 否 | 不使用 |
| 全屏 `requestFullscreen` | 否 | 无全屏按钮；可用浏览器 F11 |
| 地理定位 / 剪贴板 / 通知 | 否 | 不使用 |
| `localStorage` | 是 | 仅保存语言偏好 `skyframe.locale` |
| 网络请求 | 否 | 运行时零外部请求 |

因此作品不需要任何授权弹窗，适合展厅、机房、离线评审等受限环境。

## 7. 录制与演示配置

| 项 | 建议 |
|---|---|
| 分辨率 | **1920×1080** |
| 系统缩放 | **100%**（DPR 1），避免像素比翻倍 |
| 帧率 | 30fps（平台要求 H.264 / 30fps） |
| 画质档 | 项目只有唯一固定档，无需选择；若核显低于 28 FPS，改用 1600×900 采集后放大到 1080p |
| 浏览器 | Chrome / Edge，关闭其他标签页与硬件加速冲突插件 |
| 首屏等待 | 打开后等 **5 s** 再录，避开启动遮罩与首帧编译 |
| 镜头稳定 | 每次相机飞行后等 **1.8–2.5 s** 再切下一个动作 |
| 隐藏杂物 | 隐藏书签栏、任务栏、输入法；不要出现个人账号 |

详细分镜与等待时间见 [演示脚本与关键场景清单.md](演示脚本与关键场景清单.md)。

## 8. 已知兼容限制

1. **无 WebGL2 兜底**：不支持时无法进入，且没有说明页。
2. **无性能分级**：移动端与低端核显无法降档。
3. **高 DPI 更吃性能**：Windows 125%/150% 缩放会让实际渲染像素翻倍。
4. **移动端滚动**：页面本身不滚动，面板内部滚动；极窄屏下部件树可能需要滑动。
5. **双语字体**：使用系统字体栈，不加载 web font；不同系统字形略有差异。
6. **`file://`**：Chrome / Edge 实测可用；部分企业策略或隐私模式会限制 `localStorage`，不影响主功能。
7. **无音频**：不存在自动播放限制问题。
8. **无持久化**：除语言外不保存任何状态；刷新即重置操纵与导览。

## 9. 适配设备填写模板（可直接粘贴）

```text
适配设备类型：PC（桌面端）
补充支持：平板 / 手机触摸屏（响应式布局，建议宽度 ≥ 360px）

运行环境：
- 操作系统：Windows 10/11、macOS 12+、主流 Linux 发行版
- 浏览器：Chrome 110+ / Edge 110+ / Firefox 110+ / Safari 16.4+
- 图形能力：必须支持 WebGL2 并启用硬件加速
- 网络：不需要，全部资源内联，支持 file:// 直接打开

输入方式：
- 键鼠：左键旋转、滚轮缩放、右键平移、点击选中
- 触摸屏：单指旋转、双指捏合缩放、双指拖动平移

性能参考（Intel UHD 核显、Chrome 158、DPR 1）：
- 首屏约 3.5 秒
- 1920×1080：外观 31 FPS / 透视 28 FPS / 剖视 26 FPS / 分解 34 FPS / 材料 33 FPS
- 1600×900：外观 41 FPS / 透视 37 FPS / 剖视 33 FPS / 分解 43 FPS / 材料 40 FPS

不支持：
- VR / AR 头显
- 手柄
- 摄像头、麦克风、指针锁定、全屏 API
- 无 WebGL2 或禁用硬件加速的环境（当前无降级页）
```
