> 波音 787-9 交互式结构图鉴 —— 把一架宽体客机拆成 113 个可点击部件，用程序化三维模型讲清楚「它为什么这样设计」。

## 1. 项目定位

面向科普、教学与参赛评审的三维图鉴：不做「模型展示」，而是把整机结构、材料、机构与操作逻辑组织成可交互的教学叙事。

三条主线：

1. **整机可拆解**：外观 → 透视 → 剖视 → 分解 → 材料，五种模式回答不同层级的问题。
2. **部件可讲解**：113 条部件条目，含中英文名称、说明、关键参数与「你知道吗」；53 个部件带三维热点。
3. **机构可操作**：襟翼十档、副翼/升降舵/方向舵、平尾配平、减速板、起落架、反推、发动机、冲压空气涡轮、灯光与舷窗调光。

全部几何、涂装与动画由代码生成，仓库内没有任何外部模型或贴图资源。运行时零后端、零外部请求。

### 1.1 与同批作品的差异（摘要）

- 对比《天穹构架实验室》：对象是**民用客机**而非空间站；重心是**结构图鉴与部件讲解**而非建造时间轴与在轨机构；赛项为**用户界面设计**而非交互设计。
- 对比《AnatomyLens》：纯虚拟程序化重建，不调用摄像头、不做 AR 叠加。
- 对比《The Unseen Sanctum》：知识解释型产品，不是凝视叙事。
- 对比《Opus 541 P》：没有驾驶、物理与胜负循环，是展项式探索。

完整差异表与系列作品规避口径见 [作品命名与定位.md](作品命名与定位.md)。

## 2. 快速开始

环境要求：Node.js 22 及以上（CI 使用 Node 22，本机 Node 24 已验证）。

```bash
cd boeing
npm install
npm run dev      # 监听源码变化并重建 dist/index.html
npm run serve    # 本地预览 http://localhost:8787/
npm run build    # 生产构建（node build.mjs --min）
```

构建产物为 `dist/index.html`（本机实测约 1.04 MiB / 1064 KB，样式与脚本全部内联）。`dist/` 与 `node_modules/` 已被 `.gitignore` 忽略，首次运行必须先构建。

> **入口只有一个**：`boeing/dist/index.html`。`src/index.html` 是带 `/*__CSS__*/`、`/*__JS__*/` 占位符的模板，直接打开只会看到空壳。

## 4. 功能说明

### 4.1 五种显示模式

| 模式 | 快捷键 | 说明 |
|---|---|---|
| 外观 | `1` | 真实涂装与外形，点击任意部件查看讲解 |
| 透视 | `2` | 蒙皮半透明（青色边缘光），可直接看到并点选内部结构与系统 |
| 剖视 | `3` | 用剖切面切开蒙皮，滑块移动剖切位置，可切纵剖 / 俯剖 |
| 分解 | `4` | 按制造分段把机体分开，滑块控制分解程度 |
| 材料 | `5` | 按结构材料着色，并给出按重量的材料占比图例 |

### 4.2 面板与布局

- **顶栏**：中间为模式胶囊（当前模式用 2px 猩红指示线标记）；右侧为工具区（导览、标注、尺寸、环境光照、复位、语言、帮助）。
- **左侧部件面板**：搜索 + 8 个分组部件树；桌面端通顶显示，可一键折叠为边缘抓手。
- **右侧信息面板**：总览或选中部件详情（参数、实例数、「你知道吗」、聚焦 / 单独显示 / 透视查看）；可折叠。
- **底部参数面板**：飞行操纵 / 动画与灯光 / 显示三个标签页；顶部边缘有折叠抓手，收起后整块下滑，仅留抓手。
- **模式附加条**：剖视 / 分解 / 材料模式在模式胶囊下方出现对应的滑块或图例，外观与透视模式不显示任何附加条。

### 4.3 主题与语言

- **环境光照**：影棚（深色演播室光）/ 日光（蓝天 + 浅色地面），双段控件切换；3D 场景、环境贴图、雾、地面与尺寸线颜色同步。
- **界面语言**：中 / EN 双段控件；优先级 `?lang=en` → `localStorage.skyframe.locale` → 默认 `zh`。切换时不重建三维模型，选中与导览状态保留。

### 4.4 内容规模

| 项 | 数量 |
|---|---|
| 部件讲解 | 113 条 |
| 部件分组 | 8 组：机身 24、机翼与舵面 21、动力装置 19、尾翼 8、起落架 7、内部结构 11、客舱与货舱 8、机载系统 15 |

## 5. 技术架构

### 5.1 渲染与场景

- `src/scene/stage.js` 负责 `WebGLRenderer`、`PerspectiveCamera`（fov 32）、`OrbitControls`、程序化天穹着色器、PMREM 环境贴图、地面与停机位引导线。
- 阴影：`PCFShadowMap`，4096² 阴影贴图；像素比上限 2；ACES Filmic 色调映射。
- 后期：`EffectComposer` = `RenderPass` + 两层 `OutlinePass`（悬停白色 / 选中猩红）+ `OutputPass`。
- 布局遮挡处理：左右面板占据画面两侧，`layoutView()` 通过 `camera.setViewOffset()` 把投影中心移到未被遮挡区域的中央，并按可用宽高比决定机位远近。

### 5.2 状态与拾取

- 全局状态集中在 `main.js` 的 `S` 对象（模式、图层、剖切/分解参数、选中、导览进度、操纵值、标签页等）。
- 部件通过 `Registry` 反查：每个 mesh 构建时登记所属部件 id，拾取时用 `userData.pid` 命中讲解数据。
- 选中 / 悬停高亮走 `OutlinePass`，不为每个部件单独生成描边网格；隔框、长桁这类上百根的密集构件改为整体提亮材质，避免描边糊成一片。

### 5.3 构建

- `build.mjs` 用 esbuild 打包 `src/main.js`，读取 `src/index.html` 模板，把 CSS 与 JS 内联，输出单文件 `dist/index.html`。
- CI（`.github/workflows/pages.yml`）：推送 `main` → `npm ci` → `node build.mjs --min` → 发布 `dist/` 到 GitHub Pages。

### 5.4 国际化

- 词典按语义键组织：`src/i18n/ui.js`（界面文案）、`meta.js`（名称/单位/导览等元数据）、`parts-1~3.js`（113 条讲解）。
- `t(key, vars)` 取词并做插值，`setLocale` / `onLocaleChange` 负责运行时切换与重渲染。
- 不引入第三方 i18n 框架，避免额外请求与包体膨胀。

## 8. 已知限制

1. **`src/main.js` 偏大**（约 760 行），UI、拾取、导览、控制台混在一处，继续加功能前建议先拆分模块。
2. **无自动化测试**：没有 ESLint/Prettier、没有单测、没有 Playwright 冒烟，回归依赖人工。
3. **无画质档位**：阴影 4096、像素比上限 2，低端设备可能掉帧；1080p 核显实测最低 26 FPS（剖视）。
4. **首屏约 1 MB**：three.js 全量内联；可考虑压缩，但会牺牲离线单文件特性。
5. **无 WebGL2 降级页**：渲染器创建失败时没有兜底提示，页面会停在启动遮罩。
6. **英文文案未母语审校**；中文技术术语（如「分解」）已统一，新增词条需保持。
7. **断点未逐一截图验证**：`1340/1180/900/820` 主要靠 CSS 推演，建议接手后按真机复查。
8. **无 LICENSE 文件**：`package.json` 声明 ISC，但仓库根目录尚无许可证文本，参赛前需补齐。

详细边界见 [真实性与限制声明.md](真实性与限制声明.md)。

## 10. 维护手册

**改界面文案**：只改 `src/i18n/ui.js`，zh 与 en 必须同时新增/删除，业务代码只用 `t('key')`。

**加一个部件**：

1. 在 `src/aircraft/` 构几何并 `Registry` 登记 id；
2. `src/data/parts.js` 加条目（分组、说明、参数、你知道吗、hot、v）；
3. `src/i18n/parts-*.js` 补英文；
4. 本地 `npm run dev` 确认可拾取、信息面板正常。

**加导览步骤**：在 `src/data/tour.js` 追加，字段含标题、正文、机位、模式与选中目标；进度点自动生成。

**调主题色**：改 `src/styles.css` 顶部 token；若涉及 3D，另改 `stage.js` 的描边色与 `main.js` 的尺寸线颜色。

**改部署**：只动 `.github/workflows/pages.yml`；`dist/` 不入库，由 CI 构建。
